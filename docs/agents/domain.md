# Domain Docs

Before exploring, read `GLOSSARY.md` at the repo root, or `GLOSSARY-MAP.md` if present and the glossary files relevant to the task. Read relevant decisions in `docs/adr/`.

If those files don’t exist, proceed without flagging their absence. Create them when domain terms or decisions are resolved.

This is a single-context repo. Keep the glossary at the root and architecture decision records in `docs/adr/`.

Use glossary terms consistently in issues, proposals, hypotheses, and test names. If a needed term is missing, reconsider whether it fits the project’s vocabulary or note the gap for domain modeling.

If work conflicts with an existing ADR, call out the conflict instead of silently overriding it.
